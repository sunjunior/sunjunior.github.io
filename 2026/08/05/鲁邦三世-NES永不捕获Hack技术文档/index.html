鲁邦三世（NES / FC 汉化版）永不捕获 + 道具不减 Hack 技术文档

目标游戏：鲁邦三世：潘多拉的遗产（Lupin III: Pandora’s Legacy，汉化版）
目标：永不捕获 + 道具数量不减少
最终交付物：鲁邦三世-潘多拉的遗产-永不捕获V2_道具不减.nes
日期：2026-08-05

1. 背景与目标

本作是鲁邦三世主题的 FC/NES 游戏。游戏包含”捕获”机制（角色被逮捕后不可用）和”道具使用”机制（使用道具后数量减少）。

本次任务包含两个破解目标：

  1. 永不捕获：修改 ROM 使角色永远不会被捕获。
  2. 道具数量不减少：使用道具时，槽位道具数量维持不变。

最终交付物包含两个补丁的整合 ROM。

4. 破解一：永不捕获（V2）

4.1 真实捕获的判定

用户实际游玩 7501 帧，监控脚本自动检出多次捕获事件。关键发现：

  • 演示模式（无输入）的捕获通过 $3D 状态机触发（$C55B 写入 $FF）。
  • 真实游戏（用户操作角色移动、撞敌人）的捕获通过 $5F（角色可用性掩码）提交。

$5F 位含义：低 2 位 = 已捕获计数，bit3/bit5/bit7 = 三名角色的”可用位”（清零=被捕）。

4.3 V2 补丁（单字节修复）

核心洞察：$C214 的 AND $5F 生成清位掩码。将其改为 LDA $5F（直接读回原值），则后续 STA $5F 为无效写（回写原值），角色可用位永不丢失。

文件偏移 CPU 地址 原字节 新字节 效果
0x3C224 $C214 25 5F（AND $5F） A5 5F（LDA $5F） A=原 $5F，不生成清位掩码

补丁后指令流：C214: LDA $5F / C216: STA $5F（回写原值），随后 AND #$A8 在 A=原值上计算。$5F 永不改变 → 永不捕获、永不游戏结束。

5. 破解二：道具数量不减少

5.1 目标

游戏最上方槽位道具下方显示数量。当角色选择并使用道具后，数量减 1。需求：使用道具时数量维持不变（数量大于 0 的道具一直保持）。

5.2 分析思路

采用动态分析为主、静态反汇编为辅的策略：

  1. 确定道具槽的 RAM 布局（$0410 起，8 槽 × 21 字节）。
  2. 通过 Lua 内存写监控，定位”使用道具时数量减少”的字节。
  3. 通过全 RAM 快照对比，精确定位数量字节地址。
  4. 通过内存写回调获取 CPU 指令地址，反汇编定位扣减代码。
  5. 制作 ROM 补丁。
  6. 用 Lua 写拦截回调验证方案。

5.3 道具槽布局探索

通过反汇编 bank2 入口 $8D80（道具槽遍历例程）确认道具槽结构：$0410 起，8 槽，每槽 21 字节，步长 0x15。

槽 基址
slot0 $0410
slot1 $0425
slot2 $043A
slot3 $044F
slot4 $0464
slot5 $0479
slot6 $048E
slot7 $04A3

5.5 写回调捕获 PC 地址

方法：用 addMemoryCallback 拦截 $0204 写入，在回调中调用 emu.getState() 获取 cpu.pc。

结果：WRITE $0204=01 PC=$CD16 A=04 X=04 Y=03

回调中 PC 显示的是 DEC 指令后的下一条指令地址。真正的扣减指令在 $CD13。

核心发现：这是一个共享的”使用道具”例程，通过 X 寄存器索引不同的道具槽位。$CD13: DEC $0200,X 是所有道具扣减的唯一点（全 ROM 仅 1 处 DEC $0200,X）。

5.7 补丁方案

将 $CD13 的 DEC $0200,X（3 字节 DE 00 02）替换为 EA EA EA（NOP NOP NOP）。

0x3CD23 $CD13 DE 00 02 EA EA EA 跳过扣减，数量维持不变

7. 经验总结

  1. 数量字节不在道具槽内：道具槽 $0410-$04B7 只存 ID、冷却计时器、动画参数，数量在 $0204（OAM 区的独立字节）。

  2. 全 RAM 快照对比是最直接的方法：在可控条件下做使用前/后快照，diff 全内存，比持续监控更干净。

  3. 回调返回值可覆盖写入：addMemoryCallback 的写回调若返回整数，会覆盖原写入值，可用来做运行时拦截验证。

  4. emu.getState() 可获取 PC：在内存回调中调用 emu.getState() 得到 cpu.pc，用于定位写入指令的 ROM 地址。

  5. DEC $0200,X 是共享扣减例程：全 ROM 仅 1 处，NOP 掉即可阻止所有道具数量减少。

  6. addMemoryCallback API 参数必须写全：缺 cpuType/memType 会 core dump。枚举是 emu.callbackType.write（不是 memCallbackType）。
