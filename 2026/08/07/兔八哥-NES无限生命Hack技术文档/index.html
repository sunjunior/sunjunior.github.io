兔八哥（NES / FC）无限生命 Hack 技术文档

逆向工程 2026/08/07

目标游戏：The Bugs Bunny Crazy Castle（兔八哥疯狂城堡，Kemco, 1989）
目标：修改 NES ROM，使玩家在游戏中永远不会死亡（无限生命 / Infinite Lives）
交付物：打补丁的 ROM、IPS 补丁、Mesen2 作弊码（双重保险）
进阶交付物：死亡后原地复活（Respawn In Place）补丁（独立 ROM + IPS，见 §12）
日期：2026-08-07

1. 背景与目标

《兔八哥疯狂城堡》是 Kemco 于 1989 年推出的 FC/NES 迷宫动作游戏。玩家操控兔八哥在城堡中收集胡萝卜并躲避敌人，每死亡一次扣 1 条生命，生命归零则游戏结束（GAME OVER）回到标题。

本次任务的破解目标：

  1. 找到控制生命数的 RAM 地址。
  2. 定位所有”扣命”的代码位置。
  3. 修改 ROM，使扣命逻辑失效（无限生命）。
  4. 提供可直接使用的交付物：
    • 已打补丁的 ROM 文件；
    • 标准 IPS 补丁（可分享、可校验）；
    • 一套不依赖改 ROM 的 Mesen 作弊码作为”双保险”。

最终成果：玩家无论死亡多少次，生命数始终保持 $05，永不触发 GAME OVER。

2. ROM 与游戏信息

项目 值
文件名 The Bugs Bunny Crazy Castle.nes
文件大小 98,320 字节
文件 CRC32 DB0C3656
PRG CRC32 B10429AA
格式 iNES，Mapper 1（MMC1），水平镜像
PRG ROM 0x04 × 16KB = 64KB（4 个 bank）
CHR ROM 0x04 × 8KB = 32KB
Board / Chip NES-SBROM / MMC1B1-H，NTSC

关键地址约定

  • 文件偏移：含 16 字节 iNES 头，补丁落点以它为基准。
  • MMC1 采用 bank 切换，64KB PRG 分成 4×16KB。最后一个 bank（bank 3）固定映射在 CPU $C000-$FFFF，因此文件偏移 0xC12C（PRG 偏移 0xC11C）对应 CPU 地址 $C11C。
  • 生命数：零页 $007C，初始值 5，显示于 HUD。

4. 破解总体思路

核心思想是两条腿走路：

  • ROM 层：从源头掐断扣命写操作（改补丁，对任何模拟器/烧录卡都有效）。
  • 作弊层：用 Mesen 的 CheatCode 强制 $007C 读取恒为 $05（不改文件，双保险）。

5. 详细分析过程

5.1 无头进入真实可玩关卡（本次最大的坑）

本作没有”生命值”概念，只有”命数”，且标题→菜单→关卡牌→游戏有复杂的输入状态机，必须先在无头脚本里稳定进入真实关卡，后续一切分析才有意义。

最终方案（enter_game.lua / in_game3.lua）：

  1. 标题画面：每 120 帧按一次 START，直到 $007C == 5。
  2. 菜单确认：$007C == 5 标志着菜单 START 确认已执行 $C032 STA $7C（LDA #$05），此时进入关卡牌流程。
  3. 关卡牌：ofs_000_91F9_02_load_stage 显示关卡牌后进入等待循环 $9216-$922C，条件是 ram_btn_press AND #con_btns_SAB（$D0，即 Select/A/B 任一）后 BNE 跳出。约 90 帧后按 START 进入。
  4. 游戏开始判定：RAM 判定而非 PC 采样（原因见 §5.3）——玩家对象 $0500 的第 7 位置位即代表角色生成、游戏真正开始。

5.2 定位生命地址 $007C

进入游戏后快照全 RAM，人为触发死亡后再快照，差分锁定变化字节。玩家实体布局：

RAM 含义
$0500 玩家对象，bit7=存在（$80）
$0501 / $0502 玩家 X 低 / 高
$0503 玩家 Y

死亡时序（未补丁实测）：清零 $0500 → 约 30 帧后扣命指令执行 → $7C 从 5 → 4。

5.4 动态写跟踪（Debug 回调验证）

仅靠静态扫描仍要排除”静态存在但实际不执行”。用 Mesen Lua 的写内存回调抓每次写 $007C 的时机，再配合强制死亡注入：

  • 未补丁：清零 $0500 强制死亡 → 约 30 帧后 $C11C 执行 → $7C 5→4，与反汇编一致。
  • 死亡后回到关卡牌，START 重进，$7C 延续 4 → 完整验证”死亡→扣命→再战”闭环。

为什么用 RAM 判定而不是 PC 采样：在 endFrame 回调里采样 CPU 的 PC，结果恒为 NMI 等待点 $EED5（中断服务例程），拿不到游戏主循环的真实 PC；改为观测 $7C==5（菜单确认标记）与 $0500 bit7（玩家生成标记）两个 RAM 状态即可 100% 判定当前所处阶段。

6. 补丁实现

6.1 ROM 补丁

把唯一扣命指令 $C11C DEC $7C 替换为 EA EA（NOP NOP），共改动 2 字节：

文件偏移 PRG 偏移 CPU 地址 原字节 新字节 效果
0xC12C 0xC11C $C11C C6 7C EA EA 扣命失效，生命恒为 $05

保留后续的 LDA/BEQ 判定：因为 $7C 永远等于 5，GAME OVER 分支（$C129）永远走不到，逻辑最干净、误伤最小。初始化（$C032）、+1 道具（$C145）、奖励关 +3（$C15C）全部保留不动。

补丁后 ROM：The Bugs Bunny Crazy Castle (Infinite Lives).nes，98,320 字节不变，文件 CRC32 D21C2AE1、PRG CRC32 BB666A4B。

7. 双保险：Mesen 作弊码

7.1 原理

Mesen 的 NesCustom 作弊码格式为 AAAA:VV（地址:值），实现方式是拦截对指定地址的读取，一律返回设定值。配合”从源头 NOP 掉扣命写”的 ROM 补丁，即便将来发现漏网的分支，作弊码也能兜底。

作弊码：007C:05（生命数读取恒为 5）。

7.2 读取路径的坑（重要）

Mesen Lua 对同一地址存在两条读取路径，结果可能不同：

API 路径 是否经过作弊码
emu.read(addr, emu.memType.nesInternalRam) 直接读 RAM 缓冲 否（绕过）
emu.read(addr, emu.memType.nesMemory) (= 8) 走 DebugRead → 内存管理器 是

实测：作弊码生效时，游戏读 $7C 恒为 $05，而 nesInternalRam 读到的是真实 RAM 值（被扣到 $04）。因此：

  • 验证作弊码是否生效要用 nesMemory；
  • 观察真实生命要用 nesInternalRam（两者对照即知”作弊层是否真的在兜底”）。

7.3 作弊码文件格式

11. 关键技术结论

  1. 生命地址 $007C：零页一字节，初始 5，死亡递减，归零进 GAME OVER。
  2. 唯一扣命点 $C11C：全 64KB PRG 仅 1 处 DEC $7C（比蝙蝠侠的 5 处简单得多），NOP 掉即无限生命。初始化/奖励写点全部保留。
  3. 奖励逻辑无冲突：+1 道具（$C145 INC）与奖励关 +3（$C15C ADC #$03）照常生效，补丁不影响正向收益。
  4. NOP 的粒度：只 NOP 掉 DEC 一条，保留其后 LDA/BEQ 判定——生命恒 5，GAME OVER 分支天然不可达。
  5. 进入真实关卡是最难的环节：本作标题/菜单/关卡牌是多级输入状态机，需要 $7C==5（菜单确认）+ $0500 bit7（玩家生成）双 RAM 状态判定，逐级注入输入。
  6. 关卡牌等待循环 $9216-$922C：判定 ram_btn_press AND #$D0（Select/A/B 任一），A/B 也算进入条件。
  7. endFrame 里 PC 采样不可用：恒为 NMI 等待点 $EED5，必须改用 RAM 状态判定。
  8. 输入注入必须放 inputPolled 回调，直接 setInput 会被每帧覆盖。
  9. 作弊码读取路径分叉：验证作弊必须走 nesMemory，原始 RAM 读取会绕过。
  10. testRunner 不自动加载作弊文件：只走 GUI 的 GameLoaded 通知；无头验证用 emu.addCheat 显式注入（同底层 SetCheats）。
  11. --timeout=0 会瞬间停模拟器，脚本根本跑不起来，这是最常见的假”失败”。
  12. 死亡会重开本关而非原地续命：死亡 → $C11C DEC → JMP loc_C04B_loop → 关卡牌脚本 → 重新加载当前关，敌人/胡萝卜全部重置；无限生命只消除 GAME OVER 与扣命，不改变”死后重打本关”的机制。
  13. 死亡终结点只有一个 $D1B6：玩家与敌人的”死亡动画结束 → 对象清除”都汇聚于此，接管它即可拦截一切死亡。
  14. hack 代码必须放固定 bank 3：MMC1 bank 切换会把”散落在可切换 bank 里的 handler”瞬间换成别的字节，必须占用 $C000-$FFFF（固定 bank）的空闲区。
  15. 复活后不能动 = 输入门控问题：sub_C1A8 只在 16px 对齐或 $0512 bit5 置位时才把方向输入写进 $050B；死亡击退会打破对齐，复活 handler 必须显式置 $0512=$20，否则玩家冻结。
  16. 原地复活自带无限生命：扣命只发生在关卡重载循环 $C11C，原地复活不重载关卡 → 永不扣命，无需叠无限生命补丁。
  17. 死亡判定要写 (state & $A0) == $A0：本作死亡态可能是 $A0 或 $A4，只判 == $A0 会漏检。
  18. 无头模式下截图用 emu.getScreenBuffer()：emu.takeScreenshot() 在 --testRunner 下无视频渲染器会静默失效；getScreenBuffer() 返回 ARGB 缓冲可正常 dump（respawn_screen.lua）。

12. 进阶 Hack：死亡后原地复活（Respawn In Place）

§9.5 已确认原版/无限生命补丁的行为是”死后重开本关”。本节实现一个更友好的玩法：玩家阵亡后不重开本关，在当前画面原地复活（保留死亡时的位置与关卡状态），并给予约 4 秒无敌时间（复活瞬间的敌人不会立刻再杀死你）。

12.1 死亡流程终结点的定位：bra_D1B6

死亡动画由 sub_D012 处理，按 $0510 相位分帧播放”击退 → 下坠 → 清除”三个阶段。无论从哪一阶段结束，最终都会落到同一段代码（$D1A0 与 $D1AB 两处计数归零后都会走到）：

即”死亡动画结束 → 把该对象状态清零（对象被移除）”。整个死亡流程中”对象移除”只发生在这一处，只要接管它就能拦截一切死亡（玩家与敌人共用，敌人走 X≠0 分支）。

顺带说明：本作没有”玩家掉出屏幕”这类独立死亡路径，敌人的碰撞（sub_CCF6 → sub_CE5E）与强制死亡最后都进 $D1B6，接管它是唯一且充分的死亡钩子。

12.2 补丁设计

  • Hook：CPU $D1B6（文件偏移 0xD1C6）6 字节改为 4C 71 EB EA EA EA（JMP $EB71 + 3×NOP）。
  • Handler：43 字节，放在固定 bank 3 的 $EB71（文件偏移 0xEB81），该区原本是 MMC1 bank 3 的 $FF 空闲区，永不参与 bank 切换（这是选它的关键原因，见 §12.4 坑 1）。

12.3 无敌计时器与死亡判定

  • 复活时写 $0515 = $FF（约 4.27 秒），期间 sub_CCF6 会跳过玩家的敌人碰撞判定（$CD05-$CD28 的 invinc 分支），并闪烁显示。
  • 死亡判定统一写作 (state & $A0) == $A0：本作死亡态是 $A0 或 $A4（bit7=存在 + bit5=死亡，bit2 视掉落/击退方向），不能只判 == $A0，否则 $A4 死亡帧会漏检。

12.4 两个关键坑（都靠真实复现逼出来的）

坑 1：handler 必须放在固定 bank 3。 最初把 handler 塞进当前代码区尾部（会参与 bank 切换的 bank），结果是：玩家死亡 → JMP 进 handler → 途中 MMC1 切换 PRG bank → handler 字节立刻变成另一 bank 的数据 → 直接花屏/崩溃。改成固定 bank 3 的 $FF 区后消失。同理 hook 本身必须落在 bank 3（$D1B6 天然在 bank 3，$C000-$FFFF），所以 JMP $EB71 两段都永不被切走。

坑 2：复活后无法移动（输入被丢弃）。 首次接通”真实碰撞 → 死亡 → 原地复活”后，玩家能站住、能闪烁，但按方向键完全不动。逐帧对比（respawn_input.dat）：$F7 方向输入正确送达（=01），但移动缓存 $050B 恒为 0。根因在移动输入门控 sub_C1A8：

死亡击退（sub_E343 的 X-=8）与复活后，玩家 X 常落在非 16px 对齐的位置（如 85、60），$050B 永远为 0 → 方向输入被丢弃 → 玩家冻结。修复：复活分支把 $0512 置为 $20（bit5，”移动中”标记）→ sub_C1A8 无条件放行 → 复活后立即能动。对照实验：未打该修复时复活后按住右键 X 纹丝不动；打上后 X 28→58、85→115 均正常。

12.6 一个意外福利：生命自动恒为 5

补丁 ROM 的 0xC12C（$C11C）没有打无限生命补丁（仍是 C6 7C），但实测三轮死亡 $7C 恒为 5。原因：扣命 DEC $7C 只在关卡重载循环 $C11C 里执行（每重进一关扣一次），而原地复活根本不重载关卡——死亡 → $D1B6 → handler → 原地复活，完全绕过了 loc_C04B_loop。所以”原地复活”天然自带”不扣命”效果，无需再叠无限生命补丁。

12.7 无头验证结果（respawn_verify4.lua）

连续 3 个死亡周期，每周期：真实碰撞（第 1 周期）/ 真实死亡初始化（第 2、3 周期）→ 原地复活 → 等无敌结束 → 按住右键 30 帧验证可移动：

  • lives=5：全程不扣命（§12.6）；
  • stage=0/0：第 1 关，关卡从未重载；
  • 位置保留：死亡坐标 → 死亡动画末尾的落点（如 81→85，死亡动画会推移尸体约 +4px），复活后保留该点，不回到出生点 64；
  • 复活后可操作：每周期无敌结束后按住右键移动 30px 全通过；
  • 可反复死亡：3 周期连续验证，补丁状态不积累、不失效。

12.8 设计边界

  • 复活点 = 死亡动画结束时的坐标，若玩家在贴墙位置死亡，击退/动画可能把尸体顶进障碍区，复活后可能卡住（与 sub_E343 的 X-=8 击退方向有关）。测试中出现的 X=60/56/52 落点经 walkability 探测均可行走，暂未复现卡死；极端贴墙场景未做专项处理。
  • 无敌 255 帧结束后才恢复可被伤害状态，期间无法再次死亡，故本验证的”连续死亡”用强制死亡初始化触发（§12.2 的死亡态写法）完成第 2、3 周期。
