兔八哥（NES / FC）无限生命 Hack 技术文档

逆向工程 2026/08/07

目标游戏：The Bugs Bunny Crazy Castle（兔八哥疯狂城堡，Kemco, 1989）
目标：修改 NES ROM，使玩家在游戏中永远不会死亡（无限生命 / Infinite Lives）
交付物：打补丁的 ROM、IPS 补丁、Mesen2 作弊码（双重保险）
日期：2026-08-07

1. 背景与目标

《兔八哥疯狂城堡》是 Kemco 于 1989 年推出的 FC/NES 迷宫动作游戏。玩家操控兔八哥在城堡中收集胡萝卜并躲避敌人，每死亡一次扣 1 条生命，生命归零则游戏结束（GAME OVER）回到标题。

本次任务的破解目标：

  1. 找到控制生命数的 RAM 地址。
  2. 定位所有”扣命”的代码位置。
  3. 修改 ROM，使扣命逻辑失效（无限生命）。
  4. 提供可直接使用的交付物：
    • 已打补丁的 ROM 文件；
    • 标准 IPS 补丁（可分享、可校验）；
    • 一套不依赖改 ROM 的 Mesen 作弊码作为”双保险”。

最终成果：玩家无论死亡多少次，生命数始终保持 $05，永不触发 GAME OVER。

2. ROM 与游戏信息

项目 值
文件名 The Bugs Bunny Crazy Castle.nes
文件大小 98,320 字节
文件 CRC32 DB0C3656
PRG CRC32 B10429AA
格式 iNES，Mapper 1（MMC1），水平镜像
PRG ROM 0x04 × 16KB = 64KB（4 个 bank）
CHR ROM 0x04 × 8KB = 32KB
Board / Chip NES-SBROM / MMC1B1-H，NTSC

关键地址约定

  • 文件偏移：含 16 字节 iNES 头，补丁落点以它为基准。
  • MMC1 采用银行切换，64KB PRG 分成 4×16KB。最后一个 bank（bank 3）固定映射在 CPU $C000-$FFFF，因此文件偏移 0xC12C（PRG 偏移 0xC11C）对应 CPU 地址 $C11C。
  • 生命数：零页 $007C，初始值 5，显示于 HUD。

3. 分析环境与工具

用途 工具
模拟器 Mesen2（Linux），无头测试模式 --testRunner
反汇编 自写 6502 反汇编脚本（按 PRG bank 输出指令）
内存/执行跟踪 Mesen Lua API（addMemoryCallback、addEventCallback）
补丁生成 自写脚本生成补丁 ROM + 标准 IPS 文件

4. 破解总体思路

核心思想是两条腿走路：

  • ROM 层：从源头掐断扣命写操作（改补丁，对任何模拟器/烧录卡都有效）。
  • 作弊层：用 Mesen 的 CheatCode 强制 $007C 读取恒为 $05（不改文件，双保险）。

5. 详细分析过程

5.1 无头进入真实可玩关卡（本次最大的坑）

本作没有”生命值”概念，只有”命数”，且标题→菜单→关卡牌→游戏有复杂的输入状态机，必须先在无头脚本里稳定进入真实关卡，后续一切分析才有意义。

最终方案（enter_game.lua / in_game3.lua）：

  1. 标题画面：每 120 帧按一次 START，直到 $007C == 5。
  2. 菜单确认：$007C == 5 标志着菜单 START 确认已执行 $C032 STA $7C（LDA #$05），此时进入关卡牌流程。
  3. 关卡牌：ofs_000_91F9_02_load_stage 显示关卡牌后进入等待循环 $9216-$922C，条件是 ram_btn_press AND #con_btns_SAB（$D0，即 Select/A/B 任一）后 BNE 跳出。约 90 帧后按 START 进入。
  4. 游戏开始判定：RAM 判定而非 PC 采样（原因见 §5.3）——玩家对象 $0500 的第 7 位置位即代表角色生成、游戏真正开始。

关键事件帧数（两次运行一致）：

游戏画面经 screen_ascii.py 渲染确认：迷宫墙/梯子、兔八哥位于屏幕中部下方、白色敌人位于右上，确系第 1 关。

5.2 定位生命地址 $007C

进入游戏后快照全 RAM，人为触发死亡后再快照，差分锁定变化字节。玩家实体布局：

RAM 含义
$0500 玩家对象，bit7=存在（$80）
$0501 / $0502 玩家 X 低 / 高
$0503 玩家 Y

死亡时序（未补丁实测）：清零 $0500 → 约 30 帧后扣命指令执行 → $7C 从 5 → 4。

5.3 静态反汇编定位扣命指令

扫描 64KB PRG 中对 $007C 的所有操作，全 ROM 仅 1 处 DEC：

文件偏移 CPU 地址 机器码 语义
0xC042 $C032 85 7C 新游戏初始化生命 = 5（前一条 A9 05）
0xC12C $C11C C6 7C ★ 扣命（死亡）
0xC155 $C145 E6 7C 吃 +1 命道具
0xC16C $C15C 85 7C 奖励关结算 +3 命写回
0x93B6 $93A6 A5 7C HUD 显示生命数（读）

5.4 动态写跟踪（Debug 回调验证）

仅靠静态扫描仍要排除”静态存在但实际不执行”。用 Mesen Lua 的写内存回调抓每次写 $007C 的时机，再配合强制死亡注入：

  • 未补丁：清零 $0500 强制死亡 → 约 30 帧后 $C11C 执行 → $7C 5→4，与反汇编一致。
  • 死亡后回到关卡牌，START 重进，$7C 延续 4 → 完整验证”死亡→扣命→再战”闭环。

为什么用 RAM 判定而不是 PC 采样：在 endFrame 回调里采样 CPU 的 PC，结果恒为 NMI 等待点 $EED5（中断服务例程），拿不到游戏主循环的真实 PC；改为观测 $7C==5（菜单确认标记）与 $0500 bit7（玩家生成标记）两个 RAM 状态即可 100% 判定当前所处阶段。

6. 补丁实现

6.1 ROM 补丁

把唯一扣命指令 $C11C DEC $7C 替换为 EA EA（NOP NOP），共改动 2 字节：

文件偏移 PRG 偏移 CPU 地址 原字节 新字节 效果
0xC12C 0xC11C $C11C C6 7C EA EA 扣命失效，生命恒为 $05

保留后续的 LDA/BEQ 判定：因为 $7C 永远等于 5，GAME OVER 分支（$C129）永远走不到，逻辑最干净、误伤最小。初始化（$C032）、+1 道具（$C145）、奖励关 +3（$C15C）全部保留不动。

补丁后 ROM：The Bugs Bunny Crazy Castle (Infinite Lives).nes，98,320 字节不变，文件 CRC32 D21C2AE1、PRG CRC32 BB666A4B。

7. 双保险：Mesen 作弊码

7.1 原理

Mesen 的 NesCustom 作弊码格式为 AAAA:VV（地址:值），实现方式是拦截对指定地址的读取，一律返回设定值。配合”从源头 NOP 掉扣命写”的 ROM 补丁，即便将来发现漏网的分支，作弊码也能兜底。

作弊码：007C:05（生命数读取恒为 5）。

7.2 读取路径的坑（重要）

Mesen Lua 对同一地址存在两条读取路径，结果可能不同：

API 路径 是否经过作弊码
emu.read(addr, emu.memType.nesInternalRam) 直接读 RAM 缓冲 否（绕过）
emu.read(addr, emu.memType.nesMemory) (= 8) 走 DebugRead → 内存管理器 是

实测：作弊码生效时，游戏读 $7C 恒为 $05，而 nesInternalRam 读到的是真实 RAM 值（被扣到 $04）。因此：

  • 验证作弊码是否生效要用 nesMemory；
  • 观察真实生命要用 nesInternalRam（两者对照即知”作弊层是否真的在兜底”）。

7.3 作弊码文件格式

Mesen2 会在 GUI 加载 ROM 时自动应用 ~/.config/Mesen2/Cheats/<RomName>.json（RomName = ROM 文件名去掉扩展名，由 GetRomName() 得到）。JSON 字段为 PascalCase，枚举以字符串保存，序列化器启用了 UseStringEnumConverter：

8. 测试方法（无头自动化）

模拟器的 Lua API 配合 --testRunner 可实现完全无头（headless）的自动化测试，是本次验证的支柱。

8.1 testRunner 基本用法

退出码 含义
0 脚本正常结束（调用了 emu.stop(0)）
3 检测到掉血（测试失败）
255 Lua 错误 / 未加载 ROM

重要坑：

  1. 必须传 ROM 位置参数（FilesToLoad 校验：恰好 1 个），否则直接失败。
  2. --timeout 是毫秒；--timeout=0 会让等待循环立即结束、模拟器马上被停掉，脚本回调几乎不会执行。务必给足超时，脚本内部用 emu.stop(code) 提前正常退出。
  3. testRunner 不保存设置（DisableSaveSettings = true），不会污染用户配置。
  4. 杀进程用 pkill -x mesen，不要用 pkill -f mesen（-f 会匹配到调用它的 shell 本身）。

11. 关键技术结论

  1. 生命地址 $007C：零页一字节，初始 5，死亡递减，归零进 GAME OVER。
  2. 唯一扣命点 $C11C：全 64KB PRG 仅 1 处 DEC $7C（比蝙蝠侠的 5 处简单得多），NOP 掉即无限生命。初始化/奖励写点全部保留。
  3. 奖励逻辑无冲突：+1 道具（$C145 INC）与奖励关 +3（$C15C ADC #$03）照常生效，补丁不影响正向收益。
  4. NOP 的粒度：只 NOP 掉 DEC 一条，保留其后 LDA/BEQ 判定——生命恒 5，GAME OVER 分支天然不可达。
  5. 进入真实关卡是最难的环节：本作标题/菜单/关卡牌是多级输入状态机，需要 $7C==5（菜单确认）+ $0500 bit7（玩家生成）双 RAM 状态判定，逐级注入输入。
  6. 关卡牌等待循环 $9216-$922C：判定 ram_btn_press AND #$D0（Select/A/B 任一），A/B 也算进入条件。
  7. endFrame 里 PC 采样不可用：恒为 NMI 等待点 $EED5，必须改用 RAM 状态判定。
  8. 输入注入必须放 inputPolled 回调，直接 setInput 会被每帧覆盖。
  9. 作弊码读取路径分叉：验证作弊必须走 nesMemory，原始 RAM 读取会绕过。
  10. testRunner 不自动加载作弊文件：只走 GUI 的 GameLoaded 通知；无头验证用 emu.addCheat 显式注入（同底层 SetCheats）。
  11. --timeout=0 会瞬间停模拟器，脚本根本跑不起来，这是最常见的假”失败”。
