蝙蝠侠（NES / FC）无限生命 Hack 技术文档

逆向工程 2026/08/02

目标游戏：Batman (U) (Sunsoft, 1989)
目标：修改 NES ROM，使玩家在游戏中永远不会掉血（无限生命 / Infinite Health）
交付物：打补丁的 ROM、IPS 补丁、Mesen2 作弊码（双重保险）
日期：2026-08-01

1. 背景与目标

《蝙蝠侠》是 Sunsoft 于 1989 年推出的 FC/NES 横版动作游戏。玩家操控蝙蝠侠闯关，生命值（体力）随被敌人攻击而减少，归零即死亡。

本次任务的破解目标非常具体：

  1. 找到控制生命值的 RAM 地址。
  2. 定位所有”扣血”的代码位置。
  3. 修改 ROM，使扣血逻辑失效（无限生命）。
  4. 提供可直接使用的交付物：
    • 已打补丁的 ROM 文件；
    • 标准 IPS 补丁（可分享、可校验）；
    • 一套不依赖改 ROM 的 Mesen 作弊码作为”双保险”。

最终成果：玩家无论如何挨打，生命值始终保持满格 $08。

2. ROM 与游戏信息

项目 值
文件名 Batman (U).nes
文件大小 262,160 字节
MD5 62da40d0eafa92d8e4e17612bfd6ff7f
iNES Header 4E 45 53 1A 08 10 41 00 ...
格式 iNES，Mapper 4（MMC3），垂直镜像
PRG ROM 0x08 × 16KB = 128KB（0x20000 字节）
CHR ROM 0x10 × 8KB = 128KB（0x20000 字节）

关键地址约定

  • PRG 偏移：指相对 PRG 数据起始（文件偏移 = PRG 偏移 + 16 字节 iNES 头）。
  • MMC3 采用银行切换（bank switching），CPU 地址空间 $8000-$FFFF 由多个 bank 映射。同一条指令在不同时刻可能处于不同的 CPU 地址上，因此以 PRG 偏移为唯一基准。
  • 攻击/命中标记：零页 $00CC 的第 7 位（$80）在每次被击中时置位。

4. 破解总体思路

核心思想是两条腿走路：

  • ROM 层：从源头掐断扣血写操作（改补丁，对任何模拟器/烧录卡都有效）。
  • 作弊层：用 Mesen 的 CheatCode 强制 $00B7 读取恒为 $08（不改文件，双保险，万一补丁遗漏某个分支也能兜底）。

5. 详细分析过程

5.1 定位生命值地址

通过”受伤后观察 RAM”的差分方法定位生命值：

  1. 进入游戏（见 §8 输入注入方法）。
  2. 快照零页 + RAM（$0000-$07FF）。
  3. 让蝙蝠侠被击中一次，再次快照。
  4. 差分找出变化字节。

结果：$00B7 为生命值，满血 = $08，受伤逐级递减（8 → 7 → 6 ...），归零死亡。同帧内 $00CC 第 7 位置位（命中标记）。

5.2 静态反汇编定位扣血指令

用反汇编脚本扫描 PRG 中所有对 $00B7 的操作，重点嫌疑：

指令 机器码 语义
DEC $B7 C6 B7 生命值 -1（扣血主嫌疑）
STA $B7 85 B7 写入生命值（需看上下文）
INC $B7 / ADC / SBC — 增加/减算（补充检查）

扫描发现 5 处 DEC $B7 和 9 处 STA $B7。

5.4 伤害点完整地图（PRG 偏移）

扣血指令（需要 NOP）——共 7 处：

# PRG 偏移 原指令（机器码） 作用 补丁
1 0x009426 DEC $B7 (C6 B7) 伤害扣 1 格 EA EA
2 0x00944F DEC $B7 (C6 B7) 伤害扣 1 格 EA EA
3 0x009B0A DEC $B7 (C6 B7) 伤害扣 1 格 EA EA
4 0x00FA10 DEC $B7 (C6 B7) 伤害扣 1 格（主扣血例程） EA EA
5 0x011E31 DEC $B7 (C6 B7) 伤害扣 1 格 EA EA
6 0x01EBF3 STA $B7 (85 B7) 重伤害：SBC #$03 后写回 EA EA
7 0x01EBF9 STA $B7 (85 B7) 低血钳制：LDA #$00 后写回（秒杀） EA EA

初始化血量 STA $B7（保留不动）：
$FE82、$FE8A、$15EE8、$17D17、$17E82、$17E8A、$1C6CA、$1DC91、$1DEE8。

说明：6、7 两处是把扣减/清零结果写回生命值的 STA $B7。NOP 掉这两条写指令后，前面的运算结果（A 寄存器）不再落地，等效于免伤；若只 NOP 前面的 SBC #$03/LDA #$00，则 STA $B7 会原样写回当前血量，同样安全。本方案选择 NOP 写回指令，逻辑更干净。

7. 双保险：Mesen 作弊码

7.1 原理

Mesen 的 NesCustom 作弊码格式为 XXXX:YY（地址:值），实现方式是拦截对指定地址的读取，一律返回设定值。配合”从源头 NOP 掉扣血写”的 ROM 补丁，即便将来发现漏网的分支，作弊码也能兜底。

作弊码：00B7:08（生命值恒为满格）。

7.2 读取路径的坑（重要）

Mesen Lua 对同一地址存在两条读取路径，结果可能不同：

API 路径 是否经过作弊码
emu.read(addr, emu.memType.nesInternalRam) 直接读 RAM 缓冲 否（绕过）
emu.read(addr, emu.memType.nesMemory) (= 8) 走 DebugRead → 内存管理器 是

实测：作弊码生效时，CPU 执行读与 nesMemory 读取均返回 $08，而 nesInternalRam 读到的是原始 RAM 值（作弊前被扣到 $07）。因此：

  • 验证作弊码是否生效要用 nesMemory；
  • 观察真实血量要用 nesInternalRam（两者对照即知”作弊层是否真的在兜底”）。

8. 测试方法（无头自动化）

模拟器的 Lua API 配合 --testRunner 可实现完全无头（headless）的自动化测试，是本次验证的支柱。

8.1 testRunner 基本用法

退出码 含义
0 脚本正常结束（调用了 emu.stop(0)）
3 检测到掉血（测试失败）
255 Lua 错误 / 未加载 ROM

重要坑：

  1. 必须传 ROM 位置参数（FilesToLoad 校验：恰好 1 个），否则直接失败。
  2. --timeout 是毫秒；--timeout=0 会让等待循环立即结束、模拟器马上被停掉，脚本回调几乎不会执行。务必给足超时（如 60），脚本内部用 emu.stop(code) 提前正常退出。
  3. testRunner 不保存设置（DisableSaveSettings = true），不会污染用户配置。
  4. 杀进程用 pkill -x mesen，不要用 pkill -f mesen（-f 会匹配到调用它的 shell 本身）。

8.2 输入注入（进入游戏的关键）

9. 验证结果

9.1 补丁 ROM

  • 常规运行：20,000 帧，$00B7 始终保持 $08，仅 2 次初始化写入，0 次掉血。
  • 压力测试：21,000+ 帧内人为注入 22 次受伤事件（每次在伤害例程 $9A14 处强制 $00CC = $80 置命中标记），$00B7 从未下降。

上图为补丁 ROM 的实机运行录屏：蝙蝠侠被敌人持续攻击，但血条始终保持满格（$08），证明补丁已彻底拦截伤害。

9.2 作弊码（作用于原版 ROM）

  • 12,000+ 帧，原始 RAM 中 $B7 被 DEC 到 $07 累计 300+ 次（证明伤害事件真实发生），但游戏每一次读取 $B7 都返回 $08，从未死亡。
  • 作弊码读取路径对照：nesInternalRam 读到 $00（真实值）vs nesMemory 读到 $08（作弊值）；clearCheats 后恢复 $00。

  2. 或原版 ROM + Mesen 自动作弊码；
  3. 双保险：补丁 ROM + 作弊码同时生效。

11. 踩坑与经验总结

  1. 静态分析必须配动态验证：仅凭反汇编分不清”扣血”与”初始化”，写回调日志一锤定音。
  2. MMC3 银行切换：定位代码务必记录 PRG 偏移而非 CPU 地址，否则换 bank 后地址对不上。
  3. NOP 的粒度：优先 NOP 掉 STA $B7（写回指令）而不是前面的运算指令，逻辑最干净、误伤最小。
  4. 输入注入必须放 inputPolled 回调，直接 setInput 会被每帧覆盖。
  5. --timeout=0 会瞬间停模拟器，脚本根本跑不起来，这是最常见的假”失败”。
  6. 作弊码读取路径分叉：验证作弊必须走 nesMemory（DebugRead），原始 RAM 读取会绕过作弊。
  7. 杀 Mesen 用 pkill -x，避免误杀当前 shell。
