动机

这台 ZTE Grand S 已经被改造成常驻的 Arch Linux ARM 小主机（详见另一篇《在旧手机 Arch Linux 上搭建 Hexo 静态博客》），通过 Tailscale 远程管理，充当家庭内网的远程网关：能扫局域网设备、看系统状态。

但每次运维都要 SSH 进去敲命令，能不能直接用自然语言下指令？比如输入「扫描一下局域网有哪些设备」「分析家里有没有异常」，让 AI 自己决定调什么工具、看图判断，再返回结果？

这就是本文要做的：给手机装一个轻量级 AI agent 服务端，客户端（curl / 手机 / 网页）经 Tailscale 发指令，手机上的 agent 编排 DeepSeek 调用工具，必要时把摄像头图像交给多模态模型分析，最后回传结论。

整体架构

数据流：自然语言 → 编排层解析意图 → 调工具 → 图像回填 → 多模态推理 → 结论 → 回传。

技术栈选型

手机是 armv7l、可用内存约 1GB，所有选型以轻量、零 pip 依赖为准：

层 选型 理由
接入 Python http.server + token 鉴权 零依赖、armv7 友好
编排 自研 Python loop（约 200 行） 只有固定几个工具，比通用 agent 框架贴切可控
工具调用 DeepSeek function calling 模型直接决定调哪个工具，比 MCP 轻
模型 deepseek-flash（支持 text+image） 复用已有 key；推理 + 图像分析一个模型搞定
远程 Tailscale 100.107.4.30:8080 天然加密、无公网/端口映射

为什么不复用已装的 Pi agent？Pi 是通用 coding agent，工具集是读写文件/执行命令，跟”监控”场景不贴；HTTP 接入也较绕。自研 loop 反而更可控。

文件结构

职责边界：config 只读配置；tools 只做纯数据采集、无网络推理；agent 只做编排、不碰 HTTP；server 只做接入、不碰业务逻辑。各部分可独立测试。

踩坑记录

坑 1：占位图被 DeepSeek 拒绝。一开始用 1x1 的最小 JPEG 当占位图，DeepSeek 报 You have uploaded an unsupported image。换成一张真实的 banner.jpg（224KB）后正常。

坑 2：多模态链路报 400。报错 An assistant message with 'tool_calls' must be followed by tool messages——根因是图片 user 消息被插在 assistant(tool_calls) 和 tool 消息之间，违反 DeepSeek 的格式约束。解法就是用上面的 pending_images：先追加所有 tool 结果消息，图片最后再加。

坑 3：API key 不硬编码。key 从 /root/.pi/agent/env.sh 读取（就是之前配 DeepSeek 的地方），代码里只留读取逻辑，不落明文。

验证结果

用 mock 测通编排逻辑（不联网、不消耗 API），再接真实 API 端到端验证：

场景 结果
health 探活 / 无 token 访问 200 / 401 ✅
纯问答（不调工具） 直接回答，steps 为空 ✅
单工具（scan_lan） 正确调工具，返回网关 192.168.3.1 ✅
多模态链路 抓图→回填→DeepSeek 识图，images_analyzed=2 ✅
多轮会话 同 session_id 能引用上一轮结果 ✅

最有趣的是多模态那次：我用的是一张占位图（从近地轨道俯瞰地球的壁纸），DeepSeek 不仅准确描述了画面内容（大气层辉光、积云、星空），还敏锐地发现”两次抓图完全一样”、元数据里 source=placeholder，判断出这是占位图而非真实摄像头画面，明确表示”不能据此说家里没异常”。模型没被骗过，推理质量让我放心。

现状与后续

框架全链路已跑通，系统信息、局域网扫描、多模态分析都真实可用。唯一的遗憾是摄像头抓帧：这台 Android 4.1 + 高通 MSM 老设备的 camera HAL 不稳定，原厂相机和第三方相机 App 一进取景就崩溃（详见 master 文档的摄像头探索记录），所以 get_camera_image 目前仍返回占位图。后续可考虑 UVC 外接摄像头绕开高通 HAL，或换一台硬件更现代的设备。

这套架构的价值不在”摄像头”这一个工具，而在于自然语言 → 工具调用 → 多模态决策的通用范式：换成任何能拿到图像/数据的工具，同一套编排代码都不用改。
