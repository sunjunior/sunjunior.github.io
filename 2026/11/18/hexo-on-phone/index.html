背景

手头有一台老手机（ZTE Grand S，ARMv7 四核，1.8GB 内存），已经折腾成常驻的 Arch Linux ARM 环境，通过 Tailscale 远程 SSH 管理。这次的目标：把原本跑在 PC 上的 Hexo 博客整套迁移到手机，让手机承担构建和本地预览，确认效果后再推送 GitHub Pages。 手机只做构建与预览的载体，全球访问交给 GitHub Pages，彻底甩掉手机网络高延迟的负担。

环境

项 值
架构 armv7l（32 位），内核 3.4
内存 1.8GB（可用约 1GB）
系统 Arch Linux ARM（chroot 于 /sdcard/arch）
Node v26.13.1 / npm 12.2.2
Hexo 8.1.2 / NexT 主题 8.29.0

步骤一：迁移现成工程

把 PC 上的整个 Hexo 工程（含 node_modules、themes/next、44 篇文章）打包拷到手机的 /root/Blog。因为是同一套 Node 版本，且依赖几乎都是纯 JS（无原生 .node 模块），拷过来就能直接跑。

根因：git 2.56 用 getrandom syscall（内核 3.17+ 才有）生成临时文件名，手机内核是 3.4。

解决：编译一个 LD_PRELOAD shim 把 getrandom 重定向到 /dev/urandom，并全局注入（不用每次 export）：

别写成 /sbin/git 的包装脚本：系统里有 git-receive-pack -> git 之类的软链，会引发 cannot handle real as a builtin。全局 preload 最稳妥。

步骤三：踩坑二 —— pandoc 在 armv7 上不可用

hexo clean 后重新构建直接失败：

原工程用的是 hexo-renderer-pandoc，但 pandoc 没有 armv7 二进制（官方 release 和新版 Alpine 源都没有）。分析文章内容后发现：只有 5 篇用了 $$ 公式（主题已开 MathJax，marked 渲染后照样能解析），26 篇是标准 GFM 表格（marked 原生支持），没有任何 LaTeX \begin/脚注/定义列表。

所以直接换成 marked 渲染器，效果无损还省掉几十 MB 依赖：

同时在 _config.yml 里删掉 pandoc: 配置段。重新构建，350 个文件全部生成成功。

步骤四：踩坑三 —— 缺 date 导致文章排序错乱

发现一篇老文章「简单用GTest单元测试框架编写测试用例」被排到了首页第一位。根因是它的 front-matter 缺 date 字段——Hexo 对无 date 的文章会拿文件时间推算，而博客迁移时文件 mtime 被打乱，导致它被误判成最新。

关于自定义域名

用 blog.sunjunior.com 不需要额外付费（主域名 sunjunior.com 已拥有，子域免费；GitHub Pages 托管和 SSL 证书都免费）。配置两步：

  1. GoDaddy DNS 加 CNAME: blog → sunjunior.github.io
  2. 仓库 Settings → Pages → Custom domain 填 blog.sunjunior.com，勾 Enforce HTTPS

小结

把现成的 Hexo 博客迁到旧手机上跑，真正费劲的不是 Hexo 本身（纯 JS 依赖拷来即用），而是两个老环境问题：git 的 getrandom 兼容（LD_PRELOAD shim 全局注入）和 pandoc 无 armv7 二进制（换 marked 渲染器）。解决之后，构建、预览、部署一条龙都能在手机上完成，生成静态页面对 CPU/内存要求极低。

顺带记录：若相机类操作导致系统 hang，多半是高通 camera HAL 与第三方 App 不兼容，与 Hexo 无关。
