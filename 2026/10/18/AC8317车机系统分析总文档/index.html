2.2 为什么 USB 调试默认就是开的（证据）

  • default.prop：persist.sys.usb.config=adb、ro.adb.secure=0、ro.debuggable=1。
  • build.prop：# Active USB adb for debug, defaultly. + persist.sys.usb.activation=yes。
  • 反编译 services.jar 的 UsbDeviceManager：
    • mAdbEnabled = containsFunction(persist.sys.usb.config, "adb")；
    • setEnabledFunctions(...) 在 persist.sys.usb.activation=no 时强制 USB 功能为 none；
    • systemReady() 执行 Settings.Global.putInt("adb_enabled", mAdbEnabled ? 1 : 0)；
    • AdbSettingsObserver 仅在值变化时动作。

结论：只要启动属性不变，每次正常开机 USB 调试都自动可用。

6. 安全调测顺序与逃生方案（防变砖）

原则：先建后路，再做改动；一次只改一项；改完立刻重启验证；失败立即回滚。
排序依据不是“收益”，而是“出错后能不能救回来”——越靠前的步骤，越是你的生命线。

6.1 核心原则（务必遵守）

  1. 任何修改之前，先确认三条逃生通道都存在且演练过：U盘/PC 刷机、ADB(USB)、ADB(WiFi)。
  2. 能刷机 > 能 adb：分区级改动(init.rc/APK/内核)只有刷机能救；能 adb 只能救软件层。
  3. 改分区文件前先 adb pull 备份原文件；pm disable 是唯一“一键可逆”的改动，优先用它。
  4. 一次只改一项，改完测 3 遍冷启并记录。
  5. 不碰：CarManager / Daemon / SystemUI / MCU·CAN·T-Box·倒车；不要把 adb/桌面一起禁掉。

6.2 阶段 0 —— 先建“逃生通道”（最高优先级，在做任何修改之前）

本阶段全部是“准备与只读验证”，不影响系统行为。

6.2.1 确认并演练 U盘本地刷机（最强逃生手段）

  • 准备一个 U盘(FAT32)，放入原封不动的 V1.37 包：

  • 部分 APK 用 ProGuard 混淆，反编译伪代码可读性差。
  • LK 引导层二进制分析有限，升级模式进入方式需向 ODM 确认。
  • 固件版本 V1.37 vs 实机 V1.36，部分路径可能有差异。

附录 B. 风险红线汇总

  • 别动：CarManager / Daemon / SystemUI / MCU·CAN·T-Box·倒车 相关服务与驱动——影响驾驶安全功能。

  • 改前备份：改 /system、/vendor、APK 前先备份；刷机/OTA 后这些改动会失效。
  • 安全：ro.adb.secure=0 + 可开 WiFi 调试 ⇒ 任意 USB/同网段可获 root，注意使用环境。
  • 一次一项：每次只改一项，测三遍冷启，记录数据再继续。
  • 原始固件：一切“改镜像”的项目都要先备份原 V1.37（已保留）。
