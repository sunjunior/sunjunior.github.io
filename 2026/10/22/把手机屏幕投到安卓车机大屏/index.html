1. 背景与目标

1.1 起因

手里是一台安卓 6.0 的国产车机主机（杰发 AC8317，1024×600），原装预装了 ZLink（com.zjinnova.zlink v3.5.59），
车机自己的桌面是 eLite（安吉星车联）。

最初的需求很朴素：把手机屏幕投到车机大屏上。

原因也很现实：车机是 2020 年的老机器、1024×600 的低分屏、导航与音乐应用都是”车机版”；
而手机是荣耀 Magic7（MagicOS 9 / Android 15），分辨率 2800×1264。
想在车上用手机的导航、聊天、听书内容，就必须把手机画面送到这台大屏上。

1.2 需求澄清与两个关键修正

需求澄清过程中有两个关键修正，它们直接决定了技术路线：

最初的想象 澄清后的事实 影响
“在车机上点 = 操作手机”（需要触摸回传） 不需要 —— 用户在手机上操作，车机只是块大屏 Miracast 不再被否（它没有输入通道，但我们不需要）
“手机端别装客户端，用系统自带的” 车机侧根本没有接收端 结论反转：手机端必须装发送端

第一点修正排除了”必须支持触摸回传”这个会把方案空间砍掉一大半的约束；
第二点修正则把整个问题从”选哪个投屏协议”翻转成了”接收端不存在，怎么自己造一个接收端”。

1.3 目标与非目标

目标

  1. 把荣耀 Magic7 的屏幕显示到车机 1024×600 大屏，操作仍在手机上做（单向画面）。
  2. 日常可用：车机开机后手动点两下即可连上，手机端尽量自动化（开机自启）。
  3. 不破坏车机既有能力：不动 CarManager / 倒车影像 / 语音套件 / 原厂桌面回滚链路。
  4. 可一键回退：所有新增内容落在 /data，删包即恢复出厂状态。

非目标

非目标 原因
触摸回传（车机触摸控制手机） 需求澄清后不需要；VNC 的输入通道在 Android 6.0 车机上没有成熟方案
音频转发 本次只做画面；车机本身有独立的蓝牙音频链路
破解厂商授权 / 买激活码 不做授权绕过，只做自建方案
深度定制导航与娱乐 App 与投屏需求正交，另有文档记录

1.4 网络拓扑的决定

车机有自己的 eSIM 和 4G（T-Box 已 connected），但最终选择由手机开热点、车机连手机，而不是反过来。

原因有二：

  1. 硬件约束：车机 Wi-Fi 是单射频 2.4G 芯片（MT6630），STA + AP 硬件互斥——车机开热点时无法同时作为客户端连别的 AP。
  2. 链路复用：这样电脑也在同一网段，adb 与投屏共用一条链路，调试与投屏可以同时进行，不用来回切。

1.5 结果速览

项 结果
目标 荣耀 Magic 7 的屏幕显示到车机 1024×600 大屏，操作仍在手机上做（单向画面，不需触摸回传）
车机 杰发 AC8317（Autochips ac83xx）/ Android 6.0 / 1024×600 / userdebug 可 root
手机 荣耀 Magic 7（MagicOS 9 / Android 15）
网络 车机连手机热点，三方同网段（手机 10.208.253.57、车机 10.208.253.186、电脑 10.208.253.171）

实测数据 RFB 003.008 / 安全类型 [2,16]（VNC 密码认证）/ 密码校验通过 / 虚拟屏 840x379 / 连接 ESTABLISHED
额外完成 车机版喜马拉雅 v1.7.1 安装；车机 root；车机端单文件静态 curl

三个最值钱的结论（后面都有完整证据）：

  1. 车机没有 Miracast 接收端 —— 手机系统自带「投屏」永远发现不了它，“手机零安装”这条路不存在。
  2. ZLink 无线被三重独立阻断 —— 无 MFi 芯片证据 + Wi-Fi 芯片只支持 2.4GHz + 授权档位不含 W。
    即使花钱买激活码解锁，依然连不上。
  3. 选纯 TCP 方案（VNC）是唯一稳妥解 —— 它不碰 P2P、不碰蓝牙、不看厂商脸色，车机端还能自己装。

两个立刻生效的判断：
1. Wi-Fi 单射频 2.4G → 车机开热点时无法同时做 Wi-Fi 客户端（STA+AP 硬件互斥）→ 必须由手机当热点。
2. 没有 5GHz → 任何要求 5GHz 的无线方案（无线 CarPlay）在本机硬件层面就不成立。

1.8 GB 内存 + 零 Swap 是这台机器最硬的约束：高德 + 同行者 + 音乐三件套就吃掉近 500 MB。
loadavg 会显示 20+ 的高值，那是内核日志线程造成的假象（runqueue 实际只有 2 个可运行任务）。

结论：投屏客户端（AVNC，约 44 MB PSS、7.3 MB 安装包）属于可以接受但不能滥用的量级；
如果同时再开一路投屏 + 导航 + 音乐 + 有声书，内存就会进入紧张区。

# 阻断 性质 花钱能解决吗

4 厂商免费方案 mLink 车机版 minSdk=26 版本代差：本机 Android 6.0 装不上 ❌ 只能换车机或向厂商要旧版

所以：不建议买 ¥100 的 ZLink 激活码。 花钱只解开第 3 项，第 1、2 项依然在。
真正能绕开全部四坑的只有 外挂无线 CarPlay 盒（自带 5G 射频与自己的认证身份）。

厂商也提供免费的纯投屏方案 mLink（车机版 + 手机版双端，官方直链可下），
但实测其车机版 minSdk=26（Android 8.0）→ 装不上本机 Android 6.0，
且它内部同样依赖 Wi-Fi Direct（WifiP2pManager / P2pGroup）→ 单射频 2.4G 的老坑照踩。
这是第四道独立门槛，属纯版本代差：2020 年的车机配 2025+ 的投屏 App。

另一条社区经验也在本机得到验证：Wi-Fi 客户端模式与无线 CarPlay 互斥 —— 根因就是 §2.3 的单射频 2.4G。
本机的 ADB 正是走 WiFi，所以测无线 CarPlay 前必须先断开 adb 链路，天然冲突。

3.5 那到底什么能用

  • 有线 CarLife / 有线 CarPlay：可以（libzjcarlife.so + ZLink 两个 Activity 都在）。
  • CarLife 的无线：与 CarPlay 同门，同样受 regMode 门控，且本机无 5GHz → 也不行。
  • 安卓手机投屏：ZLink 3.5.59 根本没有这个功能（见下一节的 Manifest 清点）。

4. 问题二 车机没有原生投屏接收端

一个很自然的想法：如果车机自带 DLNA 或 Miracast 接收端，手机就能用系统自带「投屏」零安装推过去。

于是做了六路排查，结论是车机侧一个标准接收端都没有。

4.1 六路排查

# 手段 结果
1 ZLink 3.5.59 Manifest 组件清点 只有 CarPlayActivity / CarLifeActivity（均 LAUNCHER）。无 MirrorActivity、无 DlnaActivity（这两个是 5.3.8 才引入的；5.3.8 官方包才有 _zj_mirror._tcp）

4.3 结论

不是”协议支持与否”的问题，而是”接收端根本不存在”。
手机系统「投屏」本质是 Miracast 发送端，它需要对方广播 _miracast._tcp；
本机没有任何一个组件广播它，系统层也没有 WFD Sink。
⇒ 手机上必须装一个发送端 App，或者走”外挂无线盒子”路线。

# 坑 现象 解法

坑 1 和坑 2 是最容易让人误判”装好了却不好用”的两条：

7.3 一次性回退脚本

8. 方法论 这次能收敛靠的是这七条

  1. 先分清”发送端”与”接收端”。
    投屏能不能零安装，取决于接收端存不存在，而不是手机支持哪些协议。
    本例中手机支持 Miracast / DLNA / AirPlay 一大堆，车机却一个 Sink 都没有。

  2. 协议先看”有没有广播服务”，再看”有没有代码”。
    dns-sd -B _miracast._tcp + SSDP M-SEARCH + /proc/net/udp 看 1900，
    三条命令就能判死一个方案，比翻 APK 快得多。

  3. 区分”授权锁住”与”硬件做不到”。
    ZLink 的 regMode 是授权层（能花钱解），
    而 MT6630 只支持 2.4GHz 是硬件层（花钱也解不了）。
    把两者混为一谈，就会白花钱。

  4. 选纯 TCP 的方案。
    Miracast 依赖 P2P + 5GHz + 认证协商，变量太多；
    VNC / 普通 HTTP 只依赖 TCP，在这种”老 SoC + 单射频 + 厂商定制”的设备上稳得多。

  5. 静态分析给假设，实机给判决。
    反编译只能告诉你”软件会怎么判断”；
    ls /system/bin/mfi_test、getprop | grep wifi 这种一条命令，
    就能把”待验证假设”变成”已验证结论”。

  6. 先摸清”这台机器最紧的资源是什么”。
    1.8 GB 内存 + 0 Swap + 860 MB 空闲 /data + 单射频 2.4G + Mali-400 →
    这些约束直接排除了一大半”看起来可行”的方案。

  7. userdebug 车机上，先把可逆边界划清楚。
    adb root + 无 verity + SELinux 关闭 ⇒ /data 层改动都能一键回退；
    真正不可逆的只有 /system、/vendor 改动与刷机。
    本次新增的东西（AVNC、喜马拉雅 1.7.1、静态 curl）全部在 /data，删掉即回退。

手机重启后服务没起 荣耀”自启动管理”独立开关 设置 → 应用启动管理 → droidVNC-NG → 允许自启动 + 自动管理
车机连不上热点 单射频 2.4G，车机开热点时无法做 STA 必须由手机开热点、车机做客户端
无线 CarPlay 测不了 单射频 2.4G，STA 与 P2P/热点互斥 测无线 CarPlay 前先断 ADB；且本机无 5GHz，测了也不通

附录 E 安全与合规提示

  1. VNC 密码是明文挑战应答（DES），不是加密传输；RFB 协议本身不提供 TLS。
    只在自己的热点/局域网内使用，不要暴露到公网。
  2. 车机本机风险更高：ro.adb.secure=0 + 可 adb root ⇒ 同网段任意设备都可能拿到 root。
    插公共 WiFi 或借给别人用车机前，至少临时关闭 WiFi ADB（rm /data/property/persist.adb.tcp.port + reboot）。
  3. 投屏会把手机屏幕内容原样送到车机，注意导航中的私人信息、聊天通知等。
  4. 本方案不涉及破解厂商授权、不绕过 CarPlay 认证、不修改 CarManager / 倒车 / 语音等行车安全相关模块。
  5. 新增组件全部来自 F-Droid 官方仓库并核对了 SHA256；静态 curl 来自 moparisthebest/static-curl 官方 Release 并核对了 sha256。
  6. 投屏是观看性操作，请勿在驾驶过程中操作手机。
