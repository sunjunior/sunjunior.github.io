目标：基于上游 v0.14 的 NotepadNext 个人汉化分支，补全偏好设置/视图/搜索菜单中文翻译，打 Release 包并发布 AppImage
日期：2026-09-19
环境：Arch Linux，Qt 6.11.2，CMake 4.4.3，GCC 16
仓库：https://github.com/sunjunior/notepadnext ，安装包：https://github.com/sunjunior/notepadnext/releases/tag/v0.14-zh1

1. 背景

NotepadNext（上游 dail8859/NotepadNext v0.14）主界面虽有中文，但偏好设置对话框、视图/搜索菜单里仍有大量英文残留：Show menu bar、Fold All、Cut Bookmarked Lines、Mark All Occurrences 等。本次把这三处全部汉化，术语参照 Notepad++ 官方简体中文语言包，顺手修了查找对话框的间距问题，去掉帮助菜单的 Debug Info，最后打 Release 包并发布 AppImage。

2. 查找对话框：组标题与选项间距对齐

Search Mode 分组标题和第一个单选框 Normal 贴得太近，视觉间隔明显小于选项之间的间隔；Transparency 分组同理。用截图逐像素测量确认：

位置 调整前标题→首选项 选项之间
Search Mode ~2px ~17px（框间距）
Transparency ~3px ~11px

根因是 QGroupBox 标题嵌在边框线上，topMargin 给小了。改 FindReplaceDialog.ui：

  • Search Mode 组 topMargin：16 → 26
  • Transparency 组 topMargin：10 → 18

改完复测：标题→首选项与选项之间均为 17px，完全一致。

另外给该对话框（以及偏好设置对话框）加了浅色主题 QSS：复选框显示真实对勾、单选框显示实心圆点（运行时用 QPainter 生成 glyph 图，避免样式自带的色块）。

3. 偏好设置对话框汉化（23 条）

系统语言 zh_CN 加载的是 NotepadNext_zh_CN.qm。该文件 PreferencesDialog 上下文有 23 条 unfinished，直接在 .ts 里补齐，同时同步到 NotepadNext_zh.ts（两者此前缺失项完全一致）：

英文 中文
Show menu bar / toolbar / status bar 显示菜单栏/工具栏/状态栏
Restore previous session / Temporary files 恢复上次会话 / 临时文件
Translation: 语言：
Exit on last tab closed 关闭最后一个标签页时退出
Default Font / Font Size 默认字体 / 字号
Default Line Endings 默认行尾格式
Follow Current Document / Last Used Directory 跟随当前文档 / 上次使用的目录
An application restart is required… 应用某些设置需要重启程序。

其中 Windows (CR LF)、Linux (LF)、Macintosh (CR) 按已有风格保留英文原文，仅去掉 unfinished 标记。.ts 改完后构建时 qt_add_translations 自动跑 lrelease 生成 .qm 打进 :/i18n 资源，无需手工操作（.qm 内字符串是 UTF-16BE，直接 grep UTF-8 会误判为缺失）。

4. 视图/搜索菜单汉化（参照 Notepad++）

从 MainWindow.ui 提取视图/搜索两菜单全部 action，逐个查 zh_CN.ts 翻译状态，未翻译的集中补上。术语以 Notepad++ 官方 chineseSimplified.xml 为准：

  • Fold All → 折叠所有层级（NPP：折叠所有层次；本仓库已有”折叠层级”译法，统一用”层级”）
  • Unfold All → 展开所有层级，Fold/Unfold Level N → 折叠/展开层级 N（1–9）
  • Cut/Copy/Delete Bookmarked Lines → 剪切/复制/删除书签行（与 NPP 一致）
  • Mark All Occurrences → 用格式标记全部，Mark Style N → 使用格式 N，Clear Marks → 清除格式标记，Clear All Styles → 清除所有格式标记
  • 缩放指示器 Zoom: %1% → 缩放：%1%

剩余未翻译的多为快捷键名（Ctrl+N 等，无需翻译）和错误提示串，不在本次范围。

6. AppImage 打包：三个坑

仓库自带 appimage target（自动下载 linuxdeploy），但在本机 Arch 上连踩三坑：

坑 1：Qt 插件误用 Qt5 的 qmake。linuxdeploy-plugin-qt 默认找到 /usr/bin/qmake-qt5，报 Could not find Qt modules to deploy。解决：

坑 2：自带 strip 太老。Arch 新工具链接出的库含 .relr.dyn 节，linuxdeploy 内置 strip 不认识，大量 Strip call failed 后以 Failed to execute deferred operations 失败。解决：把两个 AppImage 用 --appimage-extract 解包，用系统 binutils 2.47 的 strip 替换 squashfs-root*/usr/bin/strip，再手动跑解包后的 AppRun（参数照抄 cmake/PackagingLinux.cmake 里 appimage target 的那一行，另需给插件写个 PATH 垫片）。

坑 3：单实例旧锁导致”静默退出”。凡是”一点反应没有、退出码 0”，先查 /dev/shm。之前 kill 掉的进程留下 NQd7ehOB… 锁文件，新实例误判自己是第二个实例直接 exit(0)；且 Release 下 qInfo 日志到不了控制台，看起来就是静默退出。删掉锁文件再启动即正常：

（附带教训：pkill -f "NotepadNext-v0.14" 会匹配到执行这条命令的 shell 自身，直接把自己杀掉；用 pkill -x 或 [...] 写法避开。）

8. 哪些文件进了仓库，哪些没有

这次在 src/ 下手工修改的 6 个源码文件，已全部提交并推送到 main 分支（commit 9e8bd658）：FindReplaceDialog.ui、FindReplaceDialog.cpp、MainWindow.ui、MainWindow.cpp、i18n/NotepadNext_zh_CN.ts、i18n/NotepadNext_zh.ts。别人 clone 下来就有完整源码。

构建过程产生的文件则不进仓库：build/（编译产物、AppDir/、squashfs-root-* 解包目录、下载的 linuxdeploy 等）和 .cpm-cache/（第三方依赖缓存）都已被 .gitignore 覆盖。.qm 翻译、NotepadNext 二进制、AppImage 每次构建都会重新生成，不需要、也不应该提交。验证过 git status 干净、无构建产物混入。
