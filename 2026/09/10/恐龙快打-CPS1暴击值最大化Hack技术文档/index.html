目标游戏：恐龙快打（Cadillacs & Dinosaurs / Dino, CPS1, 1993 Capcom）
目标一（暴击）：将角色攻击暴击值固定为 0xFF（255），大幅提升攻击伤害
目标二（掉落）：调整敌人武器掉落逻辑，实现”必掉指定枪械”（方案 A：猎枪 / 方案 B：M16 机关枪 48 发）
交付物：ROM 补丁（暴击值初始化 + 掉落判定逻辑，纯 ROM 修改，零依赖）
日期：2026-09-10（掉落 Hack 章节更新于 2026-09-15）

1. 背景与目标

《恐龙快打》是 Capcom 于 1993 年推出的 CPS1 街机横版清关动作游戏（美版名 dino，日版名 dinou）。玩家可从 4 名角色中选择一位，击退劫掠者并拯救恐龙。

本文覆盖两个相互独立的 Hack 主题，它们的分析手段（68000 反汇编 + MAME 实机验证）一致，但破解对象与结论各自成章：

  • 暴击值最大化（§5）：将角色隐藏的”暴击值”固定为 0xFF，大幅提升每次命中伤害。
  • 掉落枪械定制（§6、§7）：修改敌人死亡时”是否掉落 / 掉落哪种武器”的判定逻辑，实现每次击杀必掉指定枪械。

1.1 暴击值目标

游戏中每个角色拥有一个隐藏的”暴击值”（Critical Hit Value），影响攻击造成的伤害。该值越高，每次命中敌人时的伤害加成越大。默认暴击值约为 32（0x20），本次任务的目标：

  1. 定位暴击值在 RAM 中的存储地址。
  2. 找到其初始化来源（角色数据表）。
  3. 修改 ROM，使暴击值始终为最大值 0xFF（255）。
  4. 交付可用的补丁文件。

最终成果：ROM 直接烧录补丁，无需插件，暴击值恒为 FF，大幅提升角色输出。

1.2 掉落枪械目标

原版敌人死亡后的掉落由”掉落预设表 + RNG”共同决定，多数情况什么都不掉，且掉落枪械类型随机。本文通过逆向掉落判定子程序（0x24B48），提供两档补丁：

方案 掉落结果 实现
方案 A 每次击杀必掉，掉落物为默认武器（猎枪） 0x24B72 强制掉落类型 d1=1
方案 B（当前交付） 每次击杀必掉，掉落物为 M16 机关枪（48 发） 强制掉落类型 d1=5

另有同值变体（Uzi 机关枪 48 发，d1=4）可一行字节切换。

5.3 分析暴击值表

转储 0x2c9b6 区域的数据：

偏移 值 说明
0x2c9b6 0x18 (24) 角色 1 段 1
0x2c9b7 0x1c (28) 角色 1 段 2
0x2c9b8-0x2c9d2 0x20 (32) 默认值（大量填充）
0x2c9d3 0x24 (36) 高段位
0x2c9d4 0x2a (42)
0x2c9d5 0x30 (48)
… 0x20-0x40 不同角色/段位的多样值

默认暴击值 32（0x20） 占据了表的主体。不同角色和段位的暴击值分布在 24~110 之间。

陷阱： 该区域不仅包含暴击值表，还与其他道具（如手雷）的数据表共享内存。若将整表修改为 0xFF，会破坏道具数据，导致丢手雷时触发 ADDRESS ERROR 卡死。因此最终采用 §5.6 的”改指令、不改表”方案。

5.4 暴击值递减机制（踩坑：$c6 多对象共享）

反汇编寻找 $c6(aN) 的写指令，发现递减和清零位于一个通用的对象更新函数中：

这里的 A6 可以是任何对象（玩家、敌人、Boss、道具）：
- 当 A6 = 玩家时，$c6 = 暴击值（每 ~25 秒减 1）
- 当 A6 = 敌人/Boss 时，$c6 = 阶段计数器（比如 Boss 下车/显隐控制）
- 当 A6 = 道具时，$c6 = 倒计时（0x04c1ac 处还会被设 10 做秒杀倒计时）

关键踩坑：NOP 掉 0x4fe6e（subq）和 0x4fe7c（clr）后，Boss 的 $c6 不再变化→Boss 被卡在”隐藏/下车”状态无法攻击（第三关下车后 Boss 不可见）。必须恢复这两个通用指令。

5.5 最终决策：只改初始化、不动递减

经实测验证：
- 暴击值受击后不会归零或恢复原值（仅有通用计时器的慢速递减）
- 暴击值递减周期 ~25 秒，从 FF（255）到 0 约需 106 分钟，远超过一局游戏时长
- Boss 的 $c6 变化必须正常（否则 Boss 卡隐藏）

因此维持原版的递减/清零指令不变，只修改初始化指令即可满足需求。

6. 敌兵掉落机制逆向分析

掉落 Hack 是本文档第 2 大主题。本节描述”敌人死亡后掉落如何决定”，第 7 节给出两档补丁方案。

6.1 掉落判定子程序 0x24B48

敌人（或部分对象）死亡后调用 0x24B48，其判定流程：

关键结论：
- 掉落类型由 d1 决定；d1 = 掉落预设表[$96(a6)*32 + RNG(0..31)]。
- 武器索引 $26(a0) = (d1 - 1) * 2，随后由 $26 跳转表选择具体武器（见 6.3）。
- 原版 d1 == 0 时跳过掉落（bne.b 本应为 beq 语义——这是方案 A/B 的唯一修改点）。

7. 掉落 Hack：必掉指定枪械

原版敌人死亡多数不掉任何东西（d1 == 0 直接返回），掉落的随机类型也五花八门。方案 A / B 把 0x24B72-0x24B75 的”无掉落”分支改写为”强制掉落指定武器”：

7.1 方案 A：必掉猎枪（d1=1）

项目 CPU 视图（0x24B72 起） 文件偏移（cde_23a.8f）
原版 67 00 01 50（beq.w $24cc4，d1==0 不掉） 0x24B72=0x50, 0x24B73=0x67（词交换）
方案 A 66 02 72 01（bne.b $24b76; moveq #$1,d1） 0x24B72=0x02, 0x24B73=0x66, 0x24B74=0x01, 0x24B75=0x72

逻辑：d1 == 0（不掉）→ 强制 d1 = 1 → 走武器路径 → $26 = 0 → 猎枪（6 发）。实机验证：每次击杀 100% 掉猎枪。

7.2 方案 B：必掉 M16 机关枪 48 发（d1=5，当前交付）

方案 B 与方案 A 仅差一个立即数字节（moveq #$1 → moveq #$5）：

项目 CPU 视图 文件偏移（cde_23a.8f）
方案 B 66 02 72 05（bne.b $24b76; moveq #$5,d1） 0x24B74 = 0x05

逻辑：d1 == 0 → 强制 d1 = 5 → $26 = 8 → 跳转表 → M16 机关枪 48 发（0x24E5E: moveq #$30）。

7.3 同值变体：Uzi 机关枪 48 发（d1=4）

想换成 Uzi，只需文件偏移 0x24B74 = 0x04：

逻辑：d1 == 0 → 强制 d1 = 4 → $26 = 6 → 跳转表 → Uzi 机关枪 48 发（0x24E34: moveq #$30）。

7.4 补丁操作与回归验证

  • 备份原始 dino.zip 为 dino.zip.orig（已就位）。
  • 方案 A 成果备份：/tmp/dino_planA.zip（含暴击 + 方案 A）。
  • 方案 B 各枪型备份：/tmp/dino_planB_Uzi.zip（0x24B74=0x04）、/tmp/dino_planB_M16.zip（0x24B74=0x05，当前交付）。
  • 修改 cde_23a.8f 偏移 0x24B74 即可在 A / Uzi / M16 三档间切换（01/04/05）。
  • 回归要点：
    • 保留暴击值补丁（文件 0x11770/0x11772/0x11773 = 7C/FF/00）不受影响。
    • 不触碰掉落表与通用对象函数，Boss、手雷、食物/宝藏分类逻辑保持原样。
    • MAME 启动告警 cde_23a.8f WRONG CHECKSUMS 与 qsound.bin ROM NEEDS REDUMP 均为 hack ROM 预期现象。

10. 踩坑与经验总结

  1. $c6(aN) 是多用途偏移——$c6(a6) 在玩家对象上是暴击值，但在敌人/道具对象上可能是其他属性（阶段计数、显隐控制、倒计时）。NOP `subq.w #1,$c6(a6)` 时需确认上下文是玩家逻辑，否则可能破坏敌人行为。应优先定位到角色初始化表做修改，而非大范围 NOP。

  2. 暴击值表与段位（连段等级）耦合——角色连段越高，暴击值也越高（表中可见 24→28→32→36→42→48 的递增）。若将全表设为 FF，所有段位的暴击值相同，弱化了段位奖励机制。接受此副作用（或保留表的梯度但整体平移）。

  3. ROM 补丁 vs 插件方案——CPS1 无 BIOS 校验（不同于 PGM），ROM 文件可随意修改，比西游释厄传（PGM 有校验）更简单。直接修改 ROM 文件是最干净的交付方式。

  4. ROM_LOAD16_WORD_SWAP 的坑——在文件内直接搜索 CPU 地址对应的字节，必须考虑字交换：CPU 看到 0x536e，文件内存的是 0x6e53。patch 脚本需先 swap 再搜索/修改。掉落补丁的 bne.b/moveq 恰好落在字节边界上，改了文件 0x24B74 的立即数即可（见 §7）。

  5. 暴击值受击不会归零——实测玩家被打后暴击值不会恢复原值或归零，仅按通用计时器每 ~25 秒减 1 慢速消耗。初始 FF（255）足够一整局游戏（约 106 分钟），无需额外 NOP 递减。

  6. 不要大范围改数据表——暴击值表所在区域与其他道具（手雷等）的数据表共享。若整表改为 0xFF，会破坏道具数据，丢手雷时触发 ADDRESS ERROR。应改为修改读取表的指令（如 move.b #$ff,$c6(a3) 替代 move.b (a6,d1.w),$c6(a3)），完全不触碰数据区。

  7. 通用对象更新函数不可动——0x4fe6e/0x4fe7c 的 $c6 递减/清零位于一个被所有对象共用的更新函数中。NOP 掉后，Boss 的 $c6（阶段计数器）不再变化，导致第三关下车后 Boss 卡在隐藏状态无法攻击。判定多用途偏移的指令时，必须回溯其所在函数是否被多对象调用。

  8. 大范围修改前先备份——每次生成新补丁前，从 dino.7z 重新提取原版 cde_23a.8f，避免在已污染的 ROM 上迭代导致错误累积。

  9. 掉落类型值是索引而非直接武器码——d1 不是武器 ID，$26=(d1-1)*2 作为跳转表 0x24D6C 的索引。改 d1 时必须查表确认目标块的起始弹药（两个 48 发的块分别对应 Uzi/M16，d1=4/5），不能凭直觉选值。

12. 敌兵翻倍 Hack（2026-09-17）

前述章节实现了暴击值最大化与 100% M16 掉落。本节在前述成果之上新增第三大 Hack 目标——将场上所有敌人（小兵、Boss）翻倍，且不影响暴击与掉落模块。参考资源来自 zengfr 的 romhack 仓库（dino/ 目录）。

12.1 目标与挑战

项目 说明
效果 每个敌人同时出现两个（小兵 ×2、Boss ×2，掉落亦 ×2）
交付 纯 ROM 补丁，不依赖插件/内存修改器
基础 叠加在暴击 FF + M16 掉落补丁之上

核心挑战：游戏对象池（0xFFC834-0xFFD994，约 20 槽）在每帧内只支持每个出兵条目处理一次。若在同一帧内对同一条目两次调用敌兵生成器 $FDAE，会因对象初始化共享状态（全局”当前对象”指针/计数器）被覆盖，导致非确定性内存损坏——崩溃点随机变化（有时 10 秒、有时 1 分钟、有时过完第一关才崩）。

12.2 八版失败的根因总结

版本 方案 结果
v1 仅远 cave 点（$7B42C/$7BFCE/$7C09A）翻倍 无可见效果
v2 近 cave（$FD2A）+ 远 cave 全翻倍 肥肥波次崩溃
v3 + bit7 过滤（避免脚本命令被翻倍） M16 兵处崩溃
v4 + 第二个兵坐标偏移 打小兵就崩溃
v5 仅近 cave + bit7 过滤 首次过第一关，但随机崩溃（重跑复现，证明非确定性）
v6 触发值过滤（Boss 区不翻倍） 肥肥波次崩溃
v7 帧延迟翻倍（保存 a2，下一帧再 spawn） 时序错乱、未清兵就提前通关
v8（终版） 严格按 zengfr 文档：jmp.l 直跳方案 ✅ 稳定连续 2 关，全部双倍，无异常

12.3 根因：进位标志（C flag）被中间指令污染

所有 v1-v7 的共同缺陷：使用 bsr/rts 往返，cave 中的中间指令破坏了 $FDAE 返回的进位标志（C flag）。

$FD2A 之后的 walker 决策：

v1-v7 的 cave 用 rts 返回时，C 已被中间指令污染：成功时 C 被清 0 却被判失败，或失败时 C 被置 1 却继续推进 → 时序乱 / 提前通关 / 随机崩溃。

关键指令对 C/V 标志的影响：

指令 C 标志 V 标志
MOVE、CLR、MOVEQ、SUBQ、ADDQ 清零 清零
TST、ANDI、ORI 清零 清零
MOVEM 不变 不变
ST/SF（Scc） 不变 不变
JMP、RTS、BRA、BCC 不变 不变

因此保留 C 标志的关键是：不要在成功/失败分支中使用 MOVE 族指令，或干脆不返回。

12.4 zengfr 文档提供的思路

zengfr 的 dino增加敌兵翻倍.txt（原文）：

关键区别：
1. jsr $fdae（绝对长调用）——补丁区可在任意 ROM 地址，不受 bsr ±32KB 限制
2. jmp $fd32/jmp $fd3c 直接返回 walker——不 rts，彻底回避 C 标志污染
3. 补丁区 $104430（21a 芯片偏移 0x4430，原 ROM 为全零，64 字节可用）

12.5 v8 最终实现

修改点 1：$FD2A（23a 芯片）

地址 原内容 修改内容
CPU $FD2A 61 00 00 82（bsr.w $fdae） 4E F9 00 10 44 30（jmp.l $104430）

6 字节覆盖原 $FD2A-$FD2F，其余 2 字节 $FD30-$FD31 为不可达代码，无需清理。

修改点 2：$104430（21a 芯片偏移 0x4430）

暴击 + M16 补丁不变：$FD2A 只改跳转，不碰其他地址。暴击（$11770）与 M16 掉落（$24B72）完整保留。

12.6 关键编码陷阱：MOVEQ / DBRA 寄存器编码

68000 的 MOVEQ 与 DBRA 寄存器号编码在低位 bits 2-0，手拼极易出错：

意图 正确编码 错误编码（实际效果）
moveq #1,d4 78 01 7C 01 = 实际上是 D6（循环计数用垃圾 d4 → 卡死）
dbra d4,−8 51 CC FF F8 51 C4 FF F8（bit3=0）→ 解码为 SF/SUBQ 变体 → 卡死

教训：凭直觉拼字节极易出错。使用 MAME 自带反汇编器验证（src/emu/cpu/m68000/m68kdasm.c：DBRA mask 0xfff8 match 0x51c8，寄存器在 bits 2-0，故 D4 = 0x51cc）。
